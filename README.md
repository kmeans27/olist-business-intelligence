# Olist Business Intelligence

A business-intelligence trio on **Olist's public Brazilian e-commerce data**:
SQL case study, a persona-first operations dashboard, and a marketing-funnel
decision memo. Built with Python + uv (no notebooks).

## What's in here

| Path | What |
|---|---|
| `sql/` | 5 non-trivial queries (joins, window functions, percentiles, cohorts) |
| `reports/sql_results/` | CSV outputs of those queries, regenerated by `scripts/run_queries.py` |
| `dashboard/app.py` | Streamlit dashboard for a **regional operations manager** persona |
| `reports/decision_memo_data/` | Segment conversion tables with Wilson intervals (input to the memo) |
| `src/olist_bi/` | library: fetch+clean, DB schema, Wilson/uplift math |
| `tests/test_golden.py` | golden checks: SQL outputs must match independent pandas computations |

## Pipeline (uv)

```bash
uv run scripts/fetch_data.py          # 10 CSVs from GitHub mirrors -> data/raw -> data/raw_clean
uv run scripts/build_db.py            # cleaned CSVs -> SQLite (data/olist.sqlite)
uv run scripts/run_queries.py         # sql/*.sql -> reports/sql_results/*.csv
uv run scripts/make_decision_memo.py  # funnel segment tables -> reports/decision_memo_data/
uv run pytest                         # 6 golden checks
uv run streamlit run dashboard/app.py # persona dashboard
```

Data sources (no Kaggle key needed): public GitHub mirrors of the official
Kaggle datasets — `MarthaMueni/Marketing-Funnel-Olist` (10 files) and
`Kaushal00Vaid/OLIST-Brazilian-Ecommerce-Analysis` (reviews). Row counts match
the official dataset (orders 99,441 / reviews 119,255 / funnel 8,000 leads).
The geolocation file (1M rows) is intentionally not downloaded — nothing here uses it.

## Cleaning decisions (all lossy decisions documented)

- **Revenue basis = orders with an actual delivery date** (`order_delivered_customer_date != ''`),
  *not* the `order_status` string: this mirror re-encodes `completed` as `delivered`,
  so the delivery-date test is the robust one.
- `customer_id` is **an alias per order**, not a person. All person-level analysis
  (cohort repeat rate, dashboard) joins through `customer_unique_id`.
- Dates normalised to sortable ISO strings (Olist ships `2016-09-05 21:01:15` and
  `2016-09-05T14:47:00Z` forms side by side).
- Rows with empty `order_status` dropped (2 rows) — unclassifiable records.
- NULL `product_category` kept as `(not mapped)` — dropping it would silently
  erase ~3% of revenue from the category mix.

## What the data says (headline numbers, regenerated on open)

**SQL case study**
1. **Category revenue**: `health_beauty` tops at R$1.41M (9.2%), then
   `watches_gifts`, `bed_bath_table`, `sports_leisure`, `computers_accessories`.
   Top 5 categories ≈ 39% of all revenue.
2. **Seller league**: 2,970 sellers produced delivered revenue; **551 (18.6%)
   cover 80% of it**. The #1 seller alone carries 1.6%. Marketplace revenue is
   broadly distributed — no single-vendor story.
3. **Delivery risk by state**: worst p90s are obscure states — `RR` 53 days
   (n=41), `AL` 40 (n=397), `AM`/`PA` 39; `SP` (São Paulo) is best at p90=15.
   Caveat honored: low-n states rank high on rate; the table keeps `n` visible.
4. **Monthly revenue growth**: steady 30–100% MoM through 2017; **2016-12 is a
   data artifact** (R$19.62 = 2 orders — the month is essentially missing), and
   2018-08 (−4.1%) is the **truncation edge** (month cut at the 2018-09-29
   harvest date). Both are flagged in the output column, not smoothed away.
5. **Cohort repeat rate** (person-level): early cohorts ~4.5–5.3% of first-time
   buyers returned within the window; rate decays for later cohorts because the
   observation window shrinks — an honest measurement limitation, kept per-cohort.

**Decision memo — marketing funnel** (Wilson 95% intervals; overall baseline 10.53%)
- **No actionable source clears a +5pp uplift target.** `PAID_SEARCH` converts
  12.30% (n=1,586, CI 10.8–14.0, **uplift +1.8pp**) — its CI lower bound sits
  just above baseline, so growing it is *directionally* supported but small;
  `ORGANIC_SEARCH` (+1.3pp) is indistinguishable from baseline.
- `UNKNOWN` is highest at 16.7% (CI 14.6–18.9) but it is an unattributed
  source — not a lever the company can act on. Honest negative result.
- **Significantly below baseline** (ci_high < 10.53%): `EMAIL` 3.0% (CI 1.9–5.0),
  `OTHER` 2.7% (CI 1.0–6.7), `SOCIAL` 5.6% (CI 4.5–6.9), `DISPLAY` 5.1%,
  `REFERRAL` 8.5%. The supported action is **pruning these sources**, not
  "improving the funnel overall".
- Won-deal composition (1,000 closed deals file): `home_decor` 105,
  `health_beauty` 93, `car_accessories` 77, `household_utilities` 71 top the
  list — conversion targets align with the top revenue categories found in Q1,
  which supports keeping spend on those product lines.
- MDE sizing (80% power, α=0.05) says you would need **n≈1,667 leads per
  segment** to detect a 5pp lift — several segments are under that; their
  differences are reported as not-detectable, not as "no effect".

**Operations dashboard persona** (regional ops manager): KPI strip (delivered
orders, revenue, p90 days for their state) → monthly trend → risk league across
all states with AT RISK verdict → category mix. One accent color; risk is
communicated by ordering + verdict column, not a rainbow.

## Limitations (honesty ledger)

- 2016-12 gap and 2018-08 truncation are harvest artifacts — flagged, not hidden.
- Low-n states (RR, AP: n<100) have unstable percentiles; `n` is in every table.
- Funnel join matches 842 of 1,000 closed deals to the 8,000-lead sample
  (the public files are samples of the same population); rates are computed on
  matched leads only.
- p90 delivery days use `julianday` day-differences (no intra-day precision).

## Design notes

- Single accent `#c2410c`; no default palettes.
- `tests/test_golden.py` recomputes Q1 totals, Q2 coverage, Q3 percentiles,
